## Problem

How to run small LLM inference locally on CPU-first, memory-constrained hardware (e.g., Raspberry Pi 5) with low dependencies and good throughput, especially for ternary/low-bit models.

## Technique

A dependency-free C23 inference engine (static libgeist.a + CLI) with GGUF loading, zero-copy mmap/aliased weights, load-time resolution of (op,dtype,layout) to direct kernel function pointers, and first-class ternary kernels (BitNet i2_s/TQ2_0/PQ2_0) using integer dot products (ARM SDOT, AVX-512 VNNI).

## Foundation

Systems/architecture: precompute expensive dispatch/binding at model load so the decode hot path is branch-light; ternary weights {-1,0,+1} (~1.58-bit) reduce memory footprint and allow multiply-free integer dot products; memory-mapped read-only weights provide demand-paged zero-copy access; engine/application boundary keeps chat/tool/product logic outside the inference ABI.

## Compute

C23 build (gcc>=14 or Apple clang>=16, make; Linux may use OpenBLAS, optional native build). Targets ARM64 (Pi 5/Apple Silicon, dotprod), x86-64-v3 with runtime AVX-512/VNNI dispatch, portable scalar reference; experimental Metal/Vulkan. Runs BitNet 2B on 4 GB Raspberry Pi 5; model download ~1.2 GB for BitNet 2B-4T.

## Reported

README reports BitNet b1.58 2B-4T on 4 GB Raspberry Pi 5, 64-bit Raspberry Pi OS: 17.9 decode tok/s at short prompt and 15.0 tok/s at 512-token prompt, frozen protocol, 10 repeats (see benchmark/README.md, reference_runs.json). README benchmark chart reports decode speedup vs bitnet.cpp: Pi 5 BitNet decode 1.96x (prefill 0.99x), Gemma decode 1.1x vs llama.cpp; AMD Ryzen 9 9950X BitNet decode 1.9x, Gemma decode 1.1x, Llama 3.2 decode 1.0x. Same GGUF, greedy decode, both engines measured in same run on same box, thermally gated; greedy output checked bit-identical to scalar reference before speedup quoted. Metal (M1 Max, Qwen3.8-27B Q4_0) reported as 1.41x llama.cpp Metal decode, 1.12x prefill; GPU backends marked experimental.

## Reproducibility

Public code repository with Apache-2.0 license, Makefile, tests (`make lib && make test`), benchmark harness (`make bench`), benchmark methodology/docs, and reference_runs.json. Release binaries/SDKs and SHA256SUMS are published. No model-training seeds (it runs existing GGUF models); benchmark conditions described but full raw artifact set not fully audited here.

If ever explored, the relevant ideas would be: load-time kernel/dispatch binding for a fixed capability set; zero-copy memory-mapped model/data artifacts; clear engine-vs-agent ABI boundary. ## Limitations

Inference engine, not an agent/runtime for tool use, chat templates, or action authorization. Experimental/limited GPU paths (Metal/Vulkan) and narrower model/platform coverage than llama.cpp; not faster everywhere (some prefill/TQ2_0/Metal prefill cases at parity or below). C codebase carries memory-safety discipline burden. Ternary scalar path is not a numerical oracle for BitNet W2A8 semantics; GPU logits not bit-identical to CPU. No direct evidence it solves DRock's intent, prompt-budget, or false-success problems.
