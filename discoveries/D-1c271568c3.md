## Problem

Run local chat, FTS retrieval, and optional web ingest on a 2018 dual-core 8GB laptop, with inference in a self-written C engine and with tool choice outside the model.

## Technique

BitNet b1.58-style ternary weights {-1,0,+1} packed at 2 bits, an AVX2 sign-table matvec in engine/forward.c (mv_row_ternp_f2 and the Q8_0 path) with a written sum-order contract, a Windows thread pool that drops back to serial unless a startup calibration is both bit-matching and more than 25% faster, and a regex router in ui/server.py api_chat that calls kb.search, web.search, and web.ingest and then asks the model only to read a prompt the code assembled (--ask / --gt).

## Foundation

Ternary matmul: 2-bit codes, one per-tensor scale, integer sign lookup, then float accumulation. forward.c documents the AVX reduction order as the thing that is supposed to match a NumPy reference. Tool choice is a finite regex cascade (RE_ING, then RE_WEB, then the small-talk whitelist RE_CHAT, else the KB, else the web chain). The function comment says this exists because the 2B model does not do function calling.

## Compute

The published box is an i7-7500U (2 cores / 4 threads), 8GB DDR4-2133, GeForce 940MX unused. The C fast path is x86 AVX2; the ARM64 build uses the scalar loop. The Linux gcc build is serial: the pool is CreateThread and the #else branch is a for-loop. Optional tools/gpu_backend.py is PyTorch, measured on an AMD Radeon Pro W7900 48GB. lab/creeper/render.py imports playwright.sync_api and launches system Edge. The files I read have no Intel Arc or oneAPI path. docs/training.md: 5-30M params is the laptop sweet spot, a 152M full run is about 35 days on that laptop, 1.5B is about 80 GPU-hours on a free cloud container.

## Reported

README and docs/engine.md, same 2-core 8GB laptop: SIMD fast path 85.53 tok/s, stated as 41x over a 2.08 tok/s serial baseline; BitNet b1.58 2B (AIM-W 0.87GB) serial 1.99 tok/s and 3.20 tok/s with two workers. A comment in ui/server.py adds W4 at 2.63 tok/s on that machine. README, same AIM-W file on the W7900, 256/256 greedy tokens: fp32 path 13.68 tok/s and bit-identical to the C engine; bf16 path 32.96 tok/s and diverges at token 30. Research-log overview: HF greedy match on the first 9 tokens; naive speculative k=2 costs +21%; fused k=2 at break-even on compute-bound hardware; k=4 exhausts the register file. docs/training.md: hand-written backprop selftest, 29 parameters, relative error 5.7e-7. E6 dossier dated 2026-11-06, 152M continued from lang6_s43 step 255600 on a GPU: ten arms, real generalization scored 0; A1 val_exact 0.232 against a computed always-answer-0 prior of 0.2305 (5000-item SE about 0.006); A3 val_exact 0.0000 after 4000 steps; a separate 748K from-scratch run val_exact 0.144 and ans_exact 0.595; frozen language loss 1.7130 against their 1.68 line; 13-subject overall 0.1210. ## Modifications

A trial on the i5-8400 would be an AVX2 CPU bench of a BitNet 2B decoder: set AIM_WORKERS, and stay on the fp32 path the README's parity note blesses. The Arc A380 is outside this code. Putting api_chat in front of DRock would replace the action grammar with a Chinese chat/KB/web whitelist and a 32- or 48-token generation. quality() only scores scraped prose: residual length under 80 returns false immediately; shell ratio over 0.5, fewer than 3 sentence enders, density under 0.30, or short-line fraction over 0.6 also fail the page. It never reads a pptx slide count, a docx word count, or whether a created file matches a goal. Copying engine C or ui/server.py into a program you serve carries AGPL-3.0. README states lab/docs is CC-BY-NC-4.0.

## Limitations

85.53 tok/s is the matvec fast path in the engine.md ledger; 3.20 tok/s is full 2B decode on 2 cores. The pool starts serial and sets worker count to 0 when calibration mismatches or when parallel time is greater than 0.75 times serial time. UI chat asks the engine for 32 or 48 new tokens. Any auto-mode question that misses RE_CHAT and the KB is sent to the web. README calls the crawler pure stdlib; render.py imports Playwright and launches Edge. NOTICE.md names Frostig et al. as the source of the 1.58-bit method; the BitNet b1.58 paper's authors are Shuming Ma, Hongyu Wang, and coauthors. The E6 writeup says 4 of 7 arms died in bf16 NaNs and that resume may drop AdamW moment state. The post-ingest check in agent_ingest is that the new card comes back from kb.search.
