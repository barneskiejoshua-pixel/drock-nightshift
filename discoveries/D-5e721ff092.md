## Problem

Awesome-CUA is a source-backed catalog of computer-use resources, and its own pipeline treats a reachable URL, a cached body, or an HTTP 200 as insufficient to approve a record.

## Technique

Content-addressed review receipts. scripts/catalog.py fetch caches a GET only when the body SHA-256 matches the receipt, writes failures to a separate .error.json, and returns an empty body while keeping the last good cache. verify_editorial sets content_matched only after a check beyond status: a non-PDF must contain the declared terms and must not be a bot-challenge page; a PDF matches only when editorial_reviewed is true and the bytes equal the retained reviewed_sha256; a changed or missing additional_evidence receipt clears the match. Review states stay separate: curated (name, scope, summary, taxonomy checked against a first-party snapshot), metadata_verified (bibliographic identity only), candidate (a normalized identifier). Ordinary catalog build is offline; discover, harvest, and verify are explicit network commands with a 30s timeout, a 10 MB cap, and a shared budget. enrich derives licenses and mentions only from the exact receipt body and does not infer semantic relations.

## Foundation

Content-addressed snapshots (SHA-256 of the fetched bytes, plus a separate whitespace-collapsed abstract hash) and a three-way review state. Identity is canonicalized (arXiv version folding, GitHub case folding). A digest checks identity of retained bytes; methodology says it does not recreate a mutable URL. Not a learned policy.

## Compute

Search and build need Python 3.11+ and the standard library, no GPU and no model endpoint. CI, as README states it, uses Python 3.12 and Node.js 24. Network work is only the explicit scan commands (scheduled 00:07, 08:07, 16:07 UTC), with timeout=30 and a 10 MB response cap. Fits the i5-8400. The GUI models the catalog lists are other projects and are not run here.

## Reproducibility

Code and data/catalog.jsonl are in the git repo; SQLite and JSON-array exports are local products of catalog.py build, which README says makes no network calls. Tests named in README: catalog.py validate, catalog.py build --check, scripts/run_tests.py, node tests/web.test.mjs and tests/search_quality.test.mjs. Versioned v* releases ship SHA256SUMS. Hugging Face TIGER-Lab/AwesomeCUA is described as a read-only mirror whose metadata_only and github_candidates splits are unreviewed. Editorial inclusion is AI-assisted and bound to a snapshot digest, so a later byte change cannot inherit approval; curation judgments are not a seed-rerunnable experiment. I did not run validate.

## Drock application

The verification gate that already separates self_reported_ok from passed (bench.py, benchmark/arms.py) and the ARTIFACT file_exists checks in benchmark/contracts.py. Same shape as verify_editorial: a present file or a 200 is a receipt, and PASS needs a content match against a retained digest or an explicit checker. agent.py is where a claim becomes success.

## Modifications

Do not vendor the catalog or load UI-TARS/Qwen2-VL. Port the promotion rule: a checker receipt stores ok, sha256, and checker id; a body whose digest differs, a PDF/office file checked only by existence or a count, or a challenge page stays a failure receipt and cannot reuse an older pass. Keep any network call on an explicit budgeted path with a timeout, as fetch does, rather than treating a missing web action as proof of no network. Store fetched text as data with a status field. Do not rank mention counts as scores.

## Limitations

No measured agent result to transfer. Counts are one scan's population and must not be added across kinds. Title-query coverage is not completeness. A digest does not restore a changed upstream page. License detection returns null unless a standard header matches. metadata_verified is not a finding. GUI-agent checkpoints named in the highlights are out of scope for a 6 GB Arc A380 and their papers' numbers are not in this repo. The PDF path still trusts a prior editorial_reviewed flag once the bytes match, so the human/AI review remains the content check.
