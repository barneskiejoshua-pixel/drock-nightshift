## Problem

Frontier-model agents cost a lot. At every step the frontier model re-reads its whole context and does every subtask itself, easy ones included.

## Technique

Delegent wraps an unmodified Claude Code with a relay that speaks the Anthropic Messages API and routes each call by the model it names. Main-loop calls go to the frontier model. Subagent and auxiliary calls go to a small local model (SLM). For coding, the frontier model uses Claude Code's built-in Agent tool, and its subagents get the default tools in the same container. For search, a Delegate tool runs a subagent adapted from AREX-Turbo, capped at 80 steps, with four tools: search (up to 5 queries, top-10 BM25 each), visit, update_context (replaces its own history with notes) and finish (answer, evidence with sources, confidence). The frontier model sees only each subagent's final report. For search, the harness checks each evidence line against the cited document. A short steering instruction does most of the work: a user-level CLAUDE.md for coding ('delegate investigation and verification, keep own steps few'), and an appended system-prompt paragraph for search ('delegate all searching'). No router or model is trained.

## Foundation

Architecture only, no new math. A lead/worker split in which the frontier model always leads, unlike cascades and routers that pick one model per task. Savings come from two places: the subagents' tool output never enters the frontier context, and the frontier model makes fewer calls. The cost model is token pricing: $2/M uncached input, $0.10/M cached input, $10/M output including reasoning.

## Compute

A frontier API: GPT-6.1-Sol at high effort for the main runs, Claude Opus 5.5 at xhigh for the DeepSWE ablation only. SLMs served by vLLM, one GPU per replica, with a proxy pinning each subagent to one replica to keep its prefix cache. Qwen3.8-27B-FP8 ran on H200 and RTX PRO 6000 Blackwell (search: mostly RTX PRO 6000 and H100). MiniCPM5-2B, which the paper calls laptop-class, actually ran on H200, RTX PRO 6000, RTX 6000 Ada and L40S. Nothing was run on hardware near an Arc A380 with 6 GB.

## Reported

Coding, frontier $/task and relative cost. SWE-bench Verified (50 tasks): alone 46 solved, $0.244; +Qwen 46 solved, $0.108 (44%); +MiniCPM 47 solved, $0.129 (53%). SWE-bench Pro (75): alone 63, $0.617; +Qwen 63, 37%; +MiniCPM 62, 44%. DeepSWE v1.1 (50): alone 29, $2.110; +Qwen 29, 33%; +MiniCPM 30, 34%. The abstract's 67% and 66% are the DeepSWE figures. Frontier calls per task fall from 32.4 to 12.7 (Verified) and from 176.1 to 46.6 (DeepSWE). With the SLM priced at API rates (Chutes), total cost is 38-57% of baseline. Search, 694 questions: 663 solved both alone and with Qwen; relative frontier cost 41% (the abstract's 59% saving); per-set relative cost 25-63%; the SLM makes 29-496 calls per question. Instruction ablation, DeepSWE: without the instruction, Sol+Qwen solved 28 at 55% cost and Sol+MiniCPM solved 22 at 51%; with it, 29 at 33% and 30 at 34%; Sol+Sol solved 34 at 60%. With Opus 5.5 as frontier: alone 34 solved in 18 turns; with SLM 38 solved at 69% cost, because Opus already does little legwork. Savings by task size: relative cost about 0.62 under 25 frontier calls, about 0.26 over 200. Latency: median 38 min vs 25 min on DeepSWE; short Verified tasks take about 2x longer.

## Drock application

planner.py already has the inverse split: 'An LLM plans, DRock executes', with remote.ClaudeCLI and remote_web.Site as planners, and every action's result goes back to the planner. Delegent's shape there would be a delegate action: the planner hands an investigation or verification subtask to DRock's own agent loop (agent.py on the local Qwen) and gets back only a report that DRock's gate has checked. On the dev side, Claude Code working on this repo could route Agent-tool subagent calls to the local Qwen at 127.0.0.1:11435 through a Messages-API relay. The GPU is shared with DRock benchmarks, though, and CLAUDE.md records that the 4B model is weak.

## Modifications

Ollama on one A380 replaces vLLM with per-subagent replica pinning, so subagents run serially without their own prefix caches. The report must pass expect.py and the gate before the planner sees it, the way Delegent checks search evidence lines against cited documents. The delegate instruction has to fit planner.contract's brief tier: AI Mode's 8,192-character box is already tight (P-4c7aa6080e). The subagent needs a step cap, as Delegent's 80-step search cap does, plus a guard against repeated identical actions, since P-bf10bbfb17 shows the current loop guard misses those.

## Limitations

Single runs on 50-75-task sets, so 'no loss' rests on 1-task differences that are within noise. The cost counted is the frontier bill only; the SLM is not free. Latency gets worse (38 vs 25 min median), and that was on datacenter GPUs. The 2B model was only ever run on server cards. Savings shrink when the frontier model already takes few turns (Opus 5.5: 69% relative cost). Without the instruction, the 2B model lost 7 of 29 DeepSWE solves. Only coding and search were tested, mostly with GPT-6.1-Sol, and everything is built on Claude Code, which the authors say may favor Opus. The code is not available to check.
