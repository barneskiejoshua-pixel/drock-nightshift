## Problem

llama-server rebuilds the KV cache on every request even when a long token prefix is unchanged. Toki Recur is a Python daemon that keeps that prefix in an in-memory llama-server slot and sends the next request to the slot that already holds it.

## Technique

Exact longest common prefix on token ids, then llama-server cache_prompt=true on that slot. recycling.py states r = max { r' <= min(m, k) : x[1:r'] of the slot equals x[1:r'] of the new tokens }. A hit is counted only if r >= 10 (MIN_REUSE_FOR_HIT); 1..9 is a soft_hit. Session id pins a slot. Otherwise a persistent pool slot whose prefix matches at least 10 tokens wins, else the free slot with the longest token prefix, else round-robin. Chat routing tokenizes only the last user message (plus an [effort:...] line when reasoning effort is set), not the full rendered prompt. Embeddings and the SQLite/HNSW index are written on a miss and the 5% cosine / longest-token tie-break lives in index search; the engine comment says that similarity number is informational and the request path does not pick the slot from it. similarity_threshold=0.85 is stored and is not read in recycling.py. Disk save/restore and cache/tree.py are present and unused.

## Foundation

The file cites arXiv:2512.11851v1 (Pandey, 4 Dec 2025): retrieve a past prompt with a sentence embedding, then reuse KV only when that prompt is an exact token prefix. That paper reloaded serialized CPU KV into Hugging Face generate on DialoGPT-medium and reported about a 50% latency drop when overlap existed. Toki Recur keeps the exact-prefix rule and drops the CPU reload. The reuse that actually skips prefill is llama.cpp's per-slot KV with cache_prompt=true.

## Compute

A llama-server process (CUDA, ROCm, SYCL, OpenVINO, Vulkan, Metal, or CPU) plus a local Python daemon (default 127.0.0.1:8787) and an embeddings extra. KV stays in the server's memory. The published table was run on an AMD Ryzen AI MAX+ 395 / Radeon 8060S. The site's headline row is Qwen3.5-122B-A10B Q4_K_M at 65k context. On 8-16 GB machines the launcher shrinks context, floor 512. Windows is marked beta. Intel Arc is SYCL (auto on Windows) or Vulkan, or explicit OpenVINO.

## Reported

README, seven shared-prefix workloads on Qwen3.5-9B, Qwen3.6-35B-A3B, Qwen3.6-27B, and Qwen3.5-122B-A10B: TTFT down 20-96%, prefill throughput up 33-1,283%. Two controls (no shared prefix, adversarial): TTFT 14-33%, prefill 15-52%. Microbench, called 'not a benchmark': Qwen3.5-2B Q4_K_M, llama-server b1099 ROCm, same AMD box, 8192 context, 1 slot, 1,372-token prompt: cold cache_prompt false 1,372 tokens evaluated, TTFT 355 ms; same prompt again 4 tokens evaluated, TTFT 27 ms; first system-prompt line changed, 1,377 tokens, TTFT 356 ms. Site table, same AMD box, 'multiple runs': best row Qwen3.5-122B-A10B summarization TTFT +96.2%, prefill +1,282.5%, hit 97.1%, score 95.8, grade A+. Same model no_overlap: TTFT +15.1%, prefill +17.0%, hit 0.0%, score 12.0, F. Same model stress_adversarial: TTFT +33.2%, prefill +52.1%, hit 57.2%, score 64.2, D. Qwen3.5-9B agent_100: TTFT +45.0%, prefill +264.0%, hit 99.0%, score 47.3, grade F. Composite weights in the README: prefill skip 30, TTFT 25, throughput 20, hit rate 15, output equivalence 10, wall-clock 5. ## Modifications

DRock talks to Ollama, not llama-server, and the open failures are intent, prompt budget, action choice, and false success. A port would mean swapping the server, pinning one session id, leaving cache_prompt on, and ignoring the embedding index and the dormant disk KV. Chat hit-rate would still be computed on the last user message, so a stable system prefix can be reused by llama-server while Toki reports a miss. That measurement bug would have to be fixed before any DRock number meant anything, and the run would have to be on the i5-8400 / Arc A380 6 GB, not the Ryzen AI Halo.

## Limitations

One changed token anywhere in the prefix recomputes everything after it. State dies on restart, spill, or eviction. Per model and per slot. Different harness system prompts do not share a cache. MLX is serving only and gets no KV reuse. The no_overlap rows still show about +14 to +17% TTFT at 0% hit, so that slice of the gain is not prefix reuse. Several high-hit agent rows are graded F, so the composite is not the speedup. README and recycling.py disagree on how bad the removed disk path was. Windows support is beta; the author's listed machines do not include an Arc A380.
