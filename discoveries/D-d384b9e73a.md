## Problem

Whether moving bits between weight matrices (each matrix gets 2, 4 or 8 bits) can lower a small LM's next-token loss with no more parameter bytes than uniform 4-bit, and which GA parent-selection rule finds those allocations under a fixed budget of candidates.

## Technique

Weight-only post-training quantization with MLX affine quantization (group size 64). The genome holds one bit-width from {2,4,8} per eligible matrix: 186 genes on Qwen3.5-2B, 196 on Qwen3-1.7B. The constraint is a hard byte ceiling equal to the measured uniform-4 cost. A repair step demotes 8 to 4 to 2 until the genome fits, then promotes random genes while one more upgrade still fits. The initial population comes from a single-matrix sensitivity probe (each matrix tried at 2 and 8 bits against an all-4 reference) and a greedy loss-per-byte proxy, plus perturbations, uniform and random genomes. Search uses two-cut segment crossover, per-gene mutation at rate 1/L, one elite, and a global seen-set, so the budget counts distinct genomes. Three arms are compared. Arm 1 is a binary-tournament variant: 3 tournaments per generation fill a parent pool that can repeat winners and allows self-mating. Arm 2 is an Alternis-inspired rule: sort, interleave as [worst, best, 2nd-worst, 2nd-best, ...], pick one random interior center plus its 2 neighbours as the pool. Arm 3 is repaired random sampling from a prior of (.15,.80,.05) over (2,4,8). Fitness is NLL on search tokens. The finalist is chosen by validation NLL from a shortlist of the top-3 archive genomes plus the uniform and informed genomes. Held-out text and ARC are scored only after that choice is frozen.

## Foundation

Affine group quantization, w = s*q + a per 64-weight group. Constrained discrete optimization: min NLL(b) subject to C(b) <= B4, where C counts packed ints, scales, affine biases and fixed params exactly. Standard elitist genetic algorithm. Paired-seed statistics: paired-t 95% intervals, exact sign test, McNemar for ARC. No new theory.

## Compute

MLX and MLX-LM, so Apple Silicon. The paper does not state the chip, the memory or any wall-clock time; it says the chip and memory configuration were not documented and calls search cost 'substantial' without a number. Each candidate means quantizing the model at that allocation and running a forward pass over 8,192 search tokens (V3, sequence length 256). V3 is 500 distinct candidates per run x 3 arms x 10 seeds = 15,000 scored entries, plus validation (32,768 tokens) and held-out (65,536 tokens). V2 is 90 candidates per run, 2,700 entries. Below is my estimate for DRock, not measured and not from the paper. MLX does not run on this i5-8400 + Arc A380 Windows box. A llama.cpp port would need one per-tensor requantize plus one perplexity pass per candidate, likely about a minute or more each, so one 500-candidate run is many hours and a 10-seed study is weeks of the shared GPU.

## Reported

V3 (Qwen3-1.7B, 10 paired seeds, 500 candidates per run, all at 968,001,536 parameter bytes = uniform-4 = 28.13% of higher-precision bytes). Validation NLL: uniform 3.75610. Tournament 3.72122 (gain 0.03489, 95% CI [0.02407, 0.04570], 10/10 seeds better). Alternis 3.75068 (gain 0.00543, CI [-0.00094, 0.01180], 5 better). Random picked uniform in all 10 seeds. Corrected fresh held-out NLL, AG News: uniform/random 3.85462, Alternis 3.84491 (gain .00970, CI [.0007, .0188], W/T/L 5/5/0), tournament 3.79299 (gain .06163, CI [.0465, .0768], 10/0/0). IMDb: uniform/random 3.74209, Alternis 3.74170 (gain .00038, CI [-.0061, .0069], 3/5/2), tournament 3.72689 (gain .01520, CI [.0071, .0233], 10/0/0). Exact sign test p=0.00195 per corpus, unadjusted for multiple comparisons. Tournament beats Alternis on 10/10 AG seeds and 8/10 IMDb seeds. The tournament representative uses 11 matrices at 2 bits, 170 at 4 and 15 at 8; Alternis uses 9/183/4. ARC-Challenge, 400 items, one representative per method: tournament 156 (39.00%), uniform and random 163 (40.75%), Alternis 158 (39.50%). Tournament vs uniform gained 18 answers and lost 25, McNemar p=0.36, so no accuracy gain. Search traces averaged over seeds, all arms starting from best search NLL 3.773886 and Hamming diversity 70.77: random stays at 3.773886 with diversity 69.87; tournament reaches 3.738768 with diversity 14.77; Alternis reaches 3.768204 with diversity 30.16. V2 (Qwen3.5-2B, 90 candidates): uniform test NLL 3.62258; tournament 3.62119 (2 wins, 8 ties, mean gain 0.001384); random and Alternis pick uniform every seed. ARC-Easy is 59.68% for tournament vs 60.25% for uniform. GPTQ-4 at the same 1.059 GB gives NLL 3.57643 and ARC-Easy 62.75%, a bigger gain than any allocation search. A separate Qwen3-1.7B control: AWQ-4 NLL 3.70452, uniform MLX-4 3.72651, GPTQ-4 3.74152. Throughput was 'similar' in 3 local trials, with no speed claim made. Appendix B discloses that the first held-out evaluation read the wrong token arrays and was rescored on fresh arrays with the finalists unchanged.

## Reproducibility

Protocol is specified in detail: frozen seeds (101, 211, ..., 1009), revision-pinned data, disjoint split indices, SHA-256 source and data manifests, SQLite NLL cache, deterministic resume, a reproduction checklist in Appendix C, and per-seed V3 numbers in Table A1. The paper mentions an 'accompanying source archive', but the arXiv page lists no code or data link and I found none. Models (Qwen3-1.7B, Qwen3.5-2B) and datasets (AG News, IMDb, WikiText-2, ARC) are public. Single author, v1, submitted 2026-11-20, not peer reviewed.

## Drock application

No direct use. DRock serves Qwen3 GGUF through Ollama on an Arc A380. The paper's quantizer (MLX affine) is Apple-only, and its gain is text NLL on news and movie reviews, with a slightly negative, non-significant ARC result. No open DRock problem is about perplexity: they are intent parsing, action order, the gate, prompt budget and failing tests. Equal bytes also saves no VRAM, so no tier fits on the 6 GB card that did not fit before. There is one tangential link, to DRock's own evolve loop. evolve/db.py:223 parent_weights and :239 draw_parent pick parents in proportion to how many per-objective Pareto fronts a candidate sits on, a diversity-keeping rule. This paper's result (exploitative tournament beat the diversity-keeping Alternis) was measured on a single-objective problem with 500 cheap deterministic evaluations per run. The author says diversity may matter more on multiobjective fronts. DRock's evolve is multiobjective, with few candidates and a noisy benchmark, so the result does not transfer and gives no reason to change draw_parent.

## Modifications

If anyone ever tried it here: port to llama.cpp, using llama-quantize per-tensor type overrides over {Q2_K, Q4_K, Q8_0} with an imatrix. The byte ceiling would be the current Q4_K_M file size. Fitness would be the log-probability of the correct action tokens on DRock's own logged traces, not generic NLL. The held-out check would be benchmark pass count with the same paired-run noise rules DRock already uses. A plain GA or even greedy sensitivity allocation would do; ShinkaEvolve's LLM mutation is the wrong tool for a fixed bit-vector genome. Run it only when no benchmark is using the GPU.

## Limitations

Stated by the author: two Qwen models with different V2/V3 protocols; one MLX affine backend, group size 64, bits {2,4,8} and one byte target; evidence is token NLL on two corpora; one 400-item ARC subset with one representative per method; seed intervals cover search randomness only, not model or data variation; no multiplicity correction; repair, initialization and encoding shape the search, so another implementation could flip the selector ranking; search cost is not normalized against GPTQ/AWQ preparation cost. My additions: (1) The random arm never improved on its initial best (3.773886 throughout), and its 80%-four-bit prior plus repair looks weak, so 'GA beats random' partly measures that prior. (2) The tournament pool is just 3 tournament winners reused for every offspring in a generation, and the Alternis pool is 3 rank-adjacent individuals, so 'selection policy' is mixed with pool construction. (3) The held-out AG News text comes from the training split, not the official test split. (4) GPTQ alone beat all allocation search in V2. (5) The hardware is undocumented and the code is not linked, so there is no cost figure to plan against. (6) The 0.015 NLL gain on IMDb is about 1.5% perplexity; its effect on an agent's action choice is unknown.
