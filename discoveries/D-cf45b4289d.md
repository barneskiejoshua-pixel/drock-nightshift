## Problem

CPU GGUF decode with no discrete GPU: one weight read from RAM per token, SMT threads sharing cache, and swap if weights plus KV exceed physical RAM. The only DRock overlap is slow discuss-grounded turns (median 119 s).

## Technique

Go supervisor that downloads ggml-org/llama.cpp llama-server at tag b12038 and starts it with -t set to the physical core count, -tb set to logical threads, -fa on, -ctk/-ctv q8_0, --context-shift, --min-p 0.05, and --spec-type ngram-mod with draft n-max 6. The in-repo PromptLookupSpeculator is a word-level strings.Index search and is not called on the real generate path. Mock mode sleeps, emits canned paragraphs, and forces the displayed speedup to at least 5.6x.

## Foundation

Speculative decoding: a draft proposes several tokens and the target verifies them in one forward pass. llama.cpp b12038 registers the type name ngram-mod in common/speculative.cpp. NoVram's ComputeSpeedup is tokens/(tokens-acceptedDrafts). doctor and the interceptor print heuristic_tok_s*5.6, capped at 235 and 240.

## Compute

CPU and system RAM. The first real run downloads a llama.cpp CPU build from GitHub into ~/.novram/bin. No CUDA and no use of the Arc A380. An i5-8400 is 6 cores / 6 threads, AVX2, no AVX-512; 32 GB covers the Q4 models in their table. The repo is 164 KB of Go; go.mod has no dependencies.

## Reported

README and LAUNCH.md share one table, condition written as a standard commodity 8-core CPU, 16 GB RAM, AVX2, Q4_K_M, with no prompt, seed, weight hash, or log: Qwen 2.5 1.5B 52.8 to 287.1 tok/s (5.4x-6.8x, 1.43 GB); Llama 3.2 3B 30.8 to 184.5 (5.2x-6.0x, 2.75 GB); Llama 3.1 8B 16.0 to 94.2 (5.0x-5.9x, 5.54 GB); Qwen 2.5 14B 8.2 to 46.8 (4.9x-5.7x, 9.57 GB). LAUNCH.md also states 25-35% from physical-core pinning and 180-280+ tok/s from 5-7 token bursts. Those cells are not emitted by the bench code.

## Limitations

287.1 tok/s sits above the program's own doctor cap of 235, and doctor multiplies a hand formula by 5.6. PinCores is stored and never passed as a CPU affinity mask; -t only sets the thread count. Load() checks the GGUF magic and still starts the process when the RAM table would say SWAPS. The recommender's KV math is fp16 while the server is started with q8_0. Mock text plus the bench floor report a turbo win with no weights. Discuss-grounded prose rarely repeats prompt n-grams, so acceptance stays low and the speedup stays near 1x. A 1.5B Q4 file is about 1 GB; at desktop DDR rates that is a few tens of tok/s per full weight read, and 287 tok/s needs several accepted drafts on every step, which this repo never logs. First launch downloads a binary. The in-tree C bridge calls llama_sampler_sample with a null sampler and builds only if NOVRAM_HAS_LLAMA is set, which the Makefile leaves unset.
